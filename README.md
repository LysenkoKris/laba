# Отчет по выполнению лабораторных работ (№1–5)

Проект представляет собой асинхронный REST API сервис, разработанный на стеке **Python 3.13 + Litestar + SQLAlchemy 2.0**. Приложение реализует архитектуру N-уровней (Controller, Service, Repository) и работает с базой данных **PostgreSQL**.

---

## Реализованный функционал

К текущему моменту выполнены следующие этапы разработки:

1.  **Архитектура и БД:**
    *   Спроектированы ORM-модели (`User`, `Address`, `Order`, `Product`) со связями One-to-Many и Many-to-Many.
    *   Настроены асинхронные миграции (Alembic) и подключение к PostgreSQL через `asyncpg`.
    *   Реализован паттерн **Repository** для абстракции работы с данными.
    *   Реализован паттерн **Service** для бизнес-логики.
    *   Внедрение зависимостей (DI) через механизм Litestar.

2.  **Тестирование (Лабораторная №4):**
    *   Настроена среда тестирования на базе **pytest**.
    *   Внедрена система **фикстур**:
        *   Изолированная тестовая БД (**SQLite in-memory**).
        *   `TestClient` для интеграционных тестов API.
        *   Mock-объекты для изоляции unit-тестов сервисного слоя.
    *   Написаны тесты для всех слоев: модели, репозитории, сервисы, контроллеры.
    *   Настроен отчет о покрытии кода (`pytest-cov`).

3.  **Качество кода и Контейнеризация (Лабораторная №5):**
    *   Настроены линтеры и форматеры: **Black**, **Isort**, **Pylint**.
    *   Внедрен **pre-commit** для автоматической проверки кода перед коммитом.
    *   Написан **Dockerfile** для сборки образа приложения.
    *   Написан скрипт **entrypoint.sh** для управления запуском и миграциями.
    *   Настроен **docker-compose.yaml** для оркестрации сервисов (App + Postgres + pgAdmin).

## Запуск проекта через Docker

Это основной и рекомендуемый способ запуска, так как он поднимает всё окружение автоматически.

### 1. Подготовка
Убедитесь, что файл `entrypoint.sh` имеет права на выполнение:
chmod +x entrypoint.sh

### 2. Сборка и запуск
Выполните команду в корне проекта:
docker compose up --build

### 3. Доступ к сервисам
После успешного старта (в логах появится `Uvicorn running on http://0.0.0.0:8000`):

*   **API приложения:** [http://localhost:8000/users](http://localhost:8000/users)
*   **Документация (Swagger):** [http://localhost:8000/schema/swagger](http://localhost:8000/schema/swagger)
*   **pgAdmin (интерфейс БД):** [http://localhost:5050](http://localhost:5050)
    *   *Логин/Пароль:* см. в `docker-compose.yaml` (`admin@example.com` / `admin`).

### 4. Остановка
docker compose down

## Запуск тестов

Тесты можно запускать двумя способами: внутри Docker-контейнера (рекомендуется) или локально.

### Способ 1: Внутри Docker (Рекомендуемый)
Этот способ гарантирует, что тесты запускаются в том же окружении, где работает приложение.

1.  Запустите контейнеры (если не запущены):
    ```
    docker compose up -d
    ```
2.  Выполните команду запуска тестов внутри контейнера `web`:
    ```
    docker compose exec web pytest
    ```
    *Или с отчетом о покрытии:*
    ```
    docker compose exec web pytest --cov=app
    ```

### Способ 2: Локально (через venv)
Требует установленных зависимостей в локальном виртуальном окружении.

1.  Активируйте окружение:
    ```
    source .venv/bin/activate  # или .\.venv\Scripts\activate для Windows
    ```
2.  Запустите pytest:
    ```
    pytest
    ```

## 🛠 Проверка качества кода

Для проверки кода на соответствие стандартам (PEP8, импорты, ошибки) используются настроенные хуки.

**Ручной запуск всех проверок (Black, Isort, Pylint):**
pre-commit run --all-files

Если хуки установлены (`pre-commit install`), они будут запускаться автоматически при каждом `git commit`.
